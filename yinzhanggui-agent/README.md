# 银掌柜 · 银行 AI 智能体

> 一句话，把银行办了。
>
> 用户用自然语言描述需求，Agent 自主理解意图、把复杂需求拆成任务 DAG，并在三级权限与多重安全机制约束下完成真实业务操作。

**作品定位**：面向手机银行与 IM 渠道的 AI 智能体。把传统"点菜单、找入口、填表单"的 3 步以上操作，压缩为一次对话。
**技术路线**：大模型负责"理解与规划"，确定性代码负责"权限与执行"——**能力交给模型，权限交给框架**。
**演示数据**：全部账户、流水、联系人、产品均为虚构演示数据，不连接任何真实银行系统。

## 一、快速开始

### 1. 安装依赖

```bash
pip install -r requirements.txt
```

若环境禁止 pip 使用临时目录（受限沙箱、离线内网机常见报错 `Permission denied: *.whl.metadata`），使用自带引导脚本：

```bash
python tools/getdeps.py          # 从国内镜像下载 wheel 并解包到 .pylibs/
```

`.pylibs/` 会被 `run.py` 与 `conftest.py` 自动加入 `sys.path`，无需手动设置环境变量。

### 2. 启动

```bash
python run.py            # 默认 http://127.0.0.1:8000
python run.py 8080       # 指定端口
```

打开 <http://127.0.0.1:8000> 即为演示界面（无需前端构建、无需 Node）。
接口文档：<http://127.0.0.1:8000/docs>

### 3. 测试

```bash
python -m pytest         # 120 个用例, 约 1 秒
```

> 若 `pytest` 不在 PATH 中，先 `export PYTHONPATH=$PWD/.pylibs`（PowerShell：`$env:PYTHONPATH="$PWD\.pylibs"`）。

### 4. 接入真实大模型（可选）

不配置也能完整运行（走本地确定性理解器，离线可用、结果可复现）：

```bash
# 任意 OpenAI 兼容网关
export YINZHANGGUI_LLM_BASE_URL=https://api.deepseek.com/v1
export YINZHANGGUI_LLM_API_KEY=sk-xxxx
export YINZHANGGUI_LLM_MODEL=deepseek-chat
```

模型只被用于"选意图 + 抽槽位"，其输出无法改变权限分级；调用失败自动静默降级为规则引擎。

## 二·五、它到底能听懂多少种说法

赛题给的是示例句式，但用户不会照着念。所以意图理解不是"关键词匹配官网例句"，而是
**槽位化理解 + 上下文补全**：只要句子里的关键要素（谁、多少钱、哪张卡、什么目标）能抽出来，
说法怎么变都能接住；抽不出来时主动澄清，而不是猜着执行。

| 同一件事的不同说法 | 处理方式 |
|---|---|
| `给王强转200` / `给尾号3382的手机号转100` / `向王强转500` / `转500给他` | 姓名、手机号掩码、手机号尾号都能定位收款人；"他"从上文继承 |
| `下周一给房东转800` / `每月1号给房东转3000` | 时间词解析 → 预约转账，不占用当日免验额度 |
| `我们4个人AA，总共800元` / `500 块 AA，4 个人` | 总额与人数分别抽取，算出每人应收 |
| `这个月钱都花哪了` / `查一下我的交易记录` / `上个月账单` / `有没有异常扣费` | 时间范围（1/7/30/60/180/365 天）与关注点自动识别 |
| `有什么稳一点的理财` / `有什么高收益的` | 风险偏好词 → 匹配 R1–R4 不同档位 |
| `这几款理财产品有什么区别` | 对比意图 → 逐项列出风险/年化/起投/期限 |
| `我还剩多少额度` | 识别为**查询**，不会误触发调额流程 |
| `把额度调到3万` / `把单笔限额调到5000` | 识别为**变更**，走对应的确认/强验证档 |
| `办张实体储蓄卡` / `申请虚拟卡` | 实体卡与虚拟卡是两条不同的办理链路 |
| `把那个一直扣钱的关掉` | 模糊指代 → 自动定位风险最高的订阅，再让你确认 |
| `我准备给我爱人买车，我可以拿出多少钱` | 开放目标 → 实算可立即动用、动用定期的上限、每月结余与缺口 |
| `明年结婚，帮我准备 5 万，大概需要 30 万` | 目标 + 期限 + 金额 → 拆成每月储蓄计划并锁定 |
| `我妈生日快到了，帮我安排一下` | 按称谓匹配日历事件（妈妈 ≠ 爱人），锁定金额与礼物时间随之调整 |

无法确定意图时（例如"今天天气怎么样"），它**不会**硬猜，而是回一句澄清 + 能力清单 ——
这是刻意的安全设计：宁可少做，也不做错。

## 三、系统架构

```

  index.html  styles.css  app.js
        │  HTTP / JSON

app/policy.py          三级权限引擎 (阈值写在代码里, 模型无权修改, 未知动作 fail-closed)
app/security.py        注入防御 / 幻觉防护 / 异常熔断 / AST 沙箱 / 哈希链审计

app/channels.py        多渠道适配: Web / APP / IM 归一化, IM 用纯文本完成确认与验证
app/selfcheck.py       安全自检 (8 个真实探测用例)
tests/                 120 个用例: NLU / 权限 / 安全 / 六场景 / 多渠道 / 演示剧本 / 事实校验 / HTTP
tools/getdeps.py       离线依赖引导 (无 pip 权限的环境)
tools/demo.py          剧本重放 + 字幕稿生成
tools/check_web.js     前端 DOM/CSS 引用一致性检查
```

### 单次请求的执行链路

```
用户输入
  → ① 注入检测 (归一化 + 模式匹配, 先于任何模型调用)
  → ② 意图理解 (规则引擎 / LLM 增强) + 槽位补全 + 指代消解
  → ③ 任务规划 (生成 DAG)
  → ④ 权限分级 (确定性代码逐节点判定)
  → ⑤ 绿色节点直接执行 / 黄色触发确认卡 / 红色触发多因子
  → ⑥ 事实校验 (回复中的金额、卡号尾号必须来自工具真实返回)
  → ⑦ 审计落盘 (全链路哈希链)
  → 回复 + 可解释面板 (DAG / 决策 / 审计)
```

## 四、权限分级

| 级别 | 策略 | 覆盖动作 |
|---|---|---|
| 🟢 绿色 | 自动执行 | 余额、流水、账单分析、异常识别、理财查询/试算/对比、可支配资金测算、订阅清单、卡片信息、日历 |
| 🟡 黄色 | 用户确认 | 小额转账（日累计 ≤ 1000 元）、AA 收款、锁定活期资金、取消订阅、虚拟卡申请、实体卡申请、交易限额、赎回、预约下单 |
| 🔴 红色 | 强验证 | 大额转账（日累计 > 1000 元）、理财申购、卡片挂失/解挂、额度调整、修改密码 |

判定逻辑落在 `app/policy.py`：静态动作查表，金额类动作用「今日累计 + 本次金额」实时计算；未登记的动作一律按红色 fail-closed 处理。强验证支持人脸识别、短信验证码、U 盾三种方式，短信验证码一次性、180 秒过期、最多 3 次。

## 五、安全机制与赛题要求对照

| 赛题要求 | 实现 | 代码位置 |
|---|---|---|
| 幻觉防护 | 回复后置校验：所有金额与卡号尾号必须在工具返回的事实集内，否则整段替换为事实模板并告警 | `security.HallucinationGuard` |
| 注入防御 | 全角/零宽归一化 + 11 条注入模式；命中即拒绝执行、计入熔断计数 | `security.InjectionGuard` |
| 操作审计 | 每条记录含前序哈希，形成可校验的哈希链；覆盖 input/nlu/plan/policy/tool/confirm/mfa/guard/rollback | `security.AuditLog` |
| 异常熔断 | 连续 3 次失败或 2 次注入尝试 → 锁定 5 分钟，锁定期间一律拒绝 | `security.CircuitBreaker` |
| 沙箱环境 | 生成的计算表达式走 AST 白名单：禁属性访问、禁导入、禁赋值，只允许算术与内置纯函数 | `security.Sandbox` |
| 三级权限 | 确定性分级引擎，模型无法通过对话提权 | `policy.classify` |
| 中断/回退/接管 | 暂停后保留计划；失败自动逆序回滚；人工接管期间连绿色动作也需坐席确认 | `executor` |

### 多渠道一致性

同一套执行引擎服务多个渠道，换渠道不会绕过风控：

| 渠道 | 确认方式 | 强验证方式 |
|---|---|---|
| Web（本项目） | 确认卡按钮 | 弹窗选择人脸 / 短信 / U 盾 |
| IM / APP | 回复「确认执行」「取消」 | 回复 6 位短信验证码 |

```bash
curl -X POST http://127.0.0.1:8000/api/im/webhook \
  -H 'Content-Type: application/json' \
  -d '{"channel":"wechat","user_id":"u1","text":"给王强转200元"}'
# → status: awaiting_confirm, quick_replies: ["确认执行","取消"]
# 再发 {"text":"确认"} → status: done
```

`tests/test_channels.py` 覆盖"IM 里说确认也绕不过红色强验证"这一条。

## 八、已知限制

1. **账户与资金为模拟账本**，未对接真实银行核心系统；接入时替换 `app/bank.py` 的实现即可，工具层与风控层无需改动。
2. **人脸识别与 U 盾为模拟通过**，生产环境需对接行方 SDK；短信验证码回显仅限演示环境。
3. **规则引擎覆盖常见表达**，超出口径的表述会主动澄清而不是猜测执行（这是刻意的安全设计）。
4. **多轮上下文仅保留最近的联系人/金额**，不做长期记忆，避免跨会话隐私与误用风险。
5. **审计日志为本地 JSONL**，生产环境应写入 WORM 存储或集中审计平台。

## 十、动效设计（GSAP 可选）

动效在这里不是装饰，而是把抽象状态讲清楚：

| 位置 | 动效 | 想表达什么 |
|---|---|---|
| 消息气泡 | 上移淡入 | 新回复到达 |
| 确认卡 | 卡片滑入 + 明细逐条错开 | 有多个字段需要你逐项看清楚 |
| 任务 DAG | 节点按层错开出现、依赖连线逐条"生长" | 任务的因果顺序 |
| 账户余额 | 数字滚动到新值 | 这一笔到底让余额变了多少 |
| 强验证弹窗 | 弹窗缩放上浮 | 进入一个需要严肃对待的环节 |
| 审计日志 | 新条目描边闪一下 | 日志是实时的、可追溯的 |
| 一键演示 | 顶部进度条 | 演示进行到第几步 |

实现方式：`web/motion.js` 是一个统一动效层，**优先使用 GSAP，取不到则退回原生 Web Animations API**，效果一致、零依赖；
并且尊重 `prefers-reduced-motion`（系统开启"减少动态效果"时全部瞬时完成）。

### 启用真 GSAP（可选，代码零改动）

```bash
python tools/fetch_gsap.py          # 从镜像把 gsap.min.js 下到 web/vendor/
```

或手动把 `gsap.min.js` 放进 `web/vendor/`。`motion.js` 会自动检测 `window.gsap` 并切换到 GSAP 时间轴
（`window.Motion.engine` 会显示当前用的是 `gsap` 还是 `waapi`）。

GSAP 许可证：[Standard "No Charge" License](https://gsap.com/community/standard-license/) ——
自 2025-04-30 起**商业项目也免费**，含此前"会员专属"的 SplitText / MorphSVG 等插件；
唯一限制是不得用它构建与 Webflow 竞争的可视化动画搭建器。本项目属于普通 Web 应用，完全合规。
`web/vendor/gsap.min.js` 未随仓库分发，按需自取即可。
